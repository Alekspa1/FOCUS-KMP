# FOCUS: Список дел, задачи, напоминания 🎯

**FOCUS** — это легкий, быстрый и ультимативно надежный кроссплатформенный планировщик задач, созданный для тех, кому важна каждая минута. Приложение успешно запущено на Android (более 7 000 скачиваний, рейтинг 4.7 в RuStore) и полностью переведено на **Kotlin Multiplatform (KMP)** для кроссплатформенной поддержки iOS, Android и Windows с единым ядром бизнес-логики.

## 🛠 Ключевые особенности и функционал приложения

* **Полноценный системный будильник (`setAlarmClock`)**: Напоминания на Android реализованы через нативный метод `AlarmManager.setAlarmClock`. Это выводит иконку будильника в статус-бар системы и гарантирует 100% срабатывание в точную секунду, обходя любые ограничения Doze Mode и глубокого энергосбережения.
* **Защита от «киллер-процессов» (Анти-Китай)**: Реализована уникальная логика дублирующей проверки и перезапуска пропущенных будильников. Если системный `BroadcastReceiver` был заблокирован агрессивной оболочкой (MIUI/HyperOS, EMUI и др.), приложение автоматически пересчитает и восстановит актуальные будильники при ближайшем открытии.
* **Динамическое управление повторениями**: Умный механизм интервалов (каждый день / неделю / месяц / год). Приложение рассчитывает и ставит точный одноразовый будильник, а в момент его срабатывания автоматически пересчитывает дату и шедулит следующий шаг.
* **Безопасное откладывание (Инверсия ID)**: Механизм быстрого откладывания «на 10 минут» работает без риска затереть основные повторяющиеся будильники на следующие дни и без коллизий ID (используется подход отрицательных индексов `-id`).
* **Интегрированный календарь**: Полноценный календарный экран с визуальным отображением и группировкой всех запланированных дел по датам.
* **Резервное копирование**: Встроенная система экспорта/импорта (резервного копирования и восстановления) локальной базы данных для безопасности пользовательских данных.
* **Глубокая кастомизация**: Локальное сохранение настроек, динамическая смена тем оформления (Ядовитая, Деревянная, Мраморная, Платиновая и др.), адаптивные шрифты и поддержка премиум-подписок.
* **Автоматические обновления**: Встроенная система проверки выхода новых версий приложения для поддержания актуального состояния у пользователя.
* **Ориентированность на быстрый UX**: Реализован паттерн мгновенного удаления выполненных задач без захламления архива старыми делами.

## 🏗 Архитектура и Технологический стек

Проект строго следует принципам **Clean Architecture** с разделением на слои (Data, Domain, Presentation) и максимальным выносом кода в общее ядро `commonMain`.

* **Ядро (Multiplatform)**: Kotlin Multiplatform (KMP)
* **Интерфейс (UI)**: Compose Multiplatform (Единая кодовая база для UI и Календаря)
* **Управление состоянием**: MVVM на базе архитектурных `ViewModel` в `commonMain`
* **Асинхронность**: Kotlin Coroutines & Flow (линейный suspend-код для асинхронных UI-событий через `CompletableDeferred`)
* **База данных**: Room Multiplatform (KMP-версия для локального хранения задач, бэкапов и связей)
* **Внедрение зависимостей**: Koin (Multiplatform DI)
* **Работа с датами**: Kotlinx DateTime (кроссплатформенный пересчет интервалов времени)
* **Сетевой слой (Задел на будущее)**: Ktor (для грядущей реализации облачной синхронизации)
* **Разрешения**: Ручная абстракция через интерфейсы

## 📐 Как устроено шаринг логики (Архитектура Будильников)

Чтобы не дублировать код валидации и пересчета дат для каждой платформы, я изолировал UI, бизнес-правила и «железо»:

1. **Бизнес-логика (`commonMain`)**: ViewModel управляет состояниями диалогов выбора даты/времени. Валидация происходит на лету (прошедшее время отсекается в общем коде до перехода к следующему шагу). Логика расчета интервалов также едина для всех.
2. **Интерфейсы (`commonMain`)**: Объявлены общие контракты для планирования системных задач (`AlarmScheduler`) и проверки разрешений (`PermissionHandler`).
3. **Платформенный слой (`androidMain` / `iosMain` / `windowsMain`)**: Каждая платформа реализует интерфейсы по-своему. На Android под капотом заводится `setAlarmClock`, на iOS — `UNUserNotificationCenter`, на Windows — `ScheduledToastNotification`. Ответы возвращаются в общий код в виде чистых `suspend`-функций.
